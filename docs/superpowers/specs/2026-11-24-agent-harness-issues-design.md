# Agent Harness 测试反馈修复设计

**日期：** 2026-11-24  
**状态：** 已获用户确认，待用户审阅  
**范围：** 模型添加前测试、Agent 模型展示、统一聊天输入、计划执行、Agent 页面一致性、Skills 自动加载、MCP 传输扩展

## 1. 背景

用户对当前本地 Agent Harness 进行了实际操作测试，发现七类问题：

1. 添加模型时没有先测试连接，失败配置也可能直接保存；
2. Agent 配置中选择模型时展示了不必要的底层模型标识；
3. 主聊天和调试聊天的 Enter/Shift+Enter 行为不一致；
4. 灵感对话与计划并执行中的计划生成、展示或执行不连贯；
5. 从模型及插件库进入 Agent 页面、从配置页返回 Agent 列表时界面和状态不一致；
6. Agent 勾选的 Skills 无法可靠生效；
7. MCP 只有 HTTP 和 Local，缺少 SSE 与 Streamable HTTP 的区分。

本设计在现有 FastAPI、SQLite、React、React Router 和 PluginStore 架构上做增量修复，不重写整体聊天或插件架构。

## 2. 已确认的方案

采用“后端约束 + 共享前端行为”的增量方案：

- 后端负责强制模型连接测试成功后才允许新增或更新；
- 前端保留草稿内容并展示可操作的错误提示；
- 主聊天和调试聊天共用一致的键盘交互约定；
- 计划执行保留计划上下文并按步骤执行；
- `/agents` 使用唯一的 Agent 列表组件和数据状态；
- 勾选的 Skills 自动加载到模型上下文，而不是改造成工具函数；
- MCP 规范化为 `stdio`、`sse`、`streamable_http`，并兼容旧的 `http` 值。

不采用仅修改前端的方案，因为客户端可以被绕过；不进行本次范围外的全面页面或插件系统重构。

## 3. 功能设计

### 3.1 模型连接与保存

#### 候选配置测试

增加不落库的候选连接测试接口：

```text
POST /api/models/test-connection
{
  "base_url": "https://example.test/v1",
  "model": "example-model",
  "api_key": "write-only-secret"
}
```

接口行为：

- 使用候选 URL、模型标识和密钥发起最小兼容模型请求；
- 成功只返回状态和耗时，不写数据库、不写凭据库；
- 失败返回安全错误，不包含 API Key、请求体或完整响应敏感内容；
- 错误应尽量指出排查方向，例如 API Base URL、模型标识、API Key、网络或服务端状态。

#### 创建模型

`POST /api/models` 在写入数据库之前复用同一连接测试逻辑。只有测试成功后才：

1. 写入模型非密钥字段；
2. 写入系统凭据库中的模型密钥；
3. 返回模型配置。

任何测试或凭据保存失败都不能留下模型记录或密钥。前端表单的字段值在失败时保留。

#### 编辑模型

- 修改 Base URL 或模型标识前，使用现有密钥测试候选配置；测试失败则保持原配置；
- 修改密钥前，使用当前 URL 和模型标识测试新密钥；测试失败则不替换旧密钥；
- 地址、模型标识或密钥成功变化后更新测试状态；
- 原有按模型 ID 测试连接接口继续保留，用于已保存模型的重新测试。

#### 前端显示

- 模型库仍可显示显示名称、Base URL、底层模型标识和连接状态；
- Agent 配置中的模型下拉框、选中摘要只显示模型显示名称；
- API Key 只使用密码输入框，不进入列表状态、Agent 响应、备份、日志或错误提示。

### 3.2 统一聊天输入

所有聊天输入框遵循同一规则：

- `Enter` 发送；
- `Shift + Enter` 插入换行；
- 输入法组合输入期间不发送；
- 空白消息不发送；
- 正在生成时不重复提交。

主聊天和 `AgentDebugChat` 使用共享的提交键处理逻辑或共享组件，避免后续再次出现行为漂移。表单提交仍作为无键盘设备的备用发送路径。

### 3.3 计划并执行

#### 运行时流程

1. 规划调用只负责生成最多 8 步的简洁计划，不调用工具；
2. 发送 `plan` 事件，前端立即展示计划；
3. 执行上下文包含原始对话和模型生成的计划；
4. 逐步追加“只执行第 N 步”的指令；
5. 每一步发送开始和完成/失败的运行轨迹；
6. 工具调用继续遵守现有授权和审批机制；
7. 工具失败时根据原计划、已完成内容和工具错误生成剩余步骤的新计划；
8. 重新规划达到上限后停止，并返回明确的可操作错误。

修复当前普通会话运行时的上下文问题：计划追加到执行消息后不得再次用原始消息重置 `execution_messages`。调试运行也使用相同的计划展示和步骤事件语义。

#### 前端展示

- 普通聊天显示计划卡，并随着 `plan` 事件更新；
- 调试聊天显示当前调试计划和执行状态；
- 运行轨迹显示步骤编号、完成状态和重规划事件；
- 计划执行模式不把规划文本误当成最终回答，也不隐藏每步执行状态。

### 3.4 Skills 自动加载

Agent 的 `selected_skills` 作为启用列表：

- 选中的 PluginStore Skill 每次普通聊天自动加载其 `SKILL.md` 正文到模型上下文；
- 调试聊天使用同样的加载规则；
- 未选中的 Skill 不加载；
- 保留旧版 `skill_directory` 的兼容和自动匹配行为，但明确选择的 Skill 优先；
- Skill 内容作为受约束的参考资料注入系统上下文，不提升为高于系统规则的指令，也不注册为模型工具函数；
- Skill 不存在、frontmatter 无效或文件读取失败时，运行轨迹记录 Skill 名称和失败原因，不再静默吞掉问题；
- 配置页面的选择列表来源与运行时 PluginStore 保持一致。

MCP 和 Python Tool 仍是独立的模型工具调用能力，不与 Skill 指令加载混淆。

### 3.5 Agent 页面与状态统一

`/agents` 是唯一标准 Agent 列表页和组件来源：

- AgentListPage 负责列表布局、空状态、配置、使用、新建和删除操作；
- 模型及插件库的 Agent Tab 复用 AgentListPage，不再维护另一套 Agent 卡片布局；
- Agent 数据由 App 统一加载和更新，避免插件库和 Agent 页面各自拥有过期副本；
- 新建、保存、删除后更新 App 的共享列表；
- 配置页返回 `/agents`；
- 模型库 Agent 入口、配置页返回入口和其他管理入口的视觉与交互一致；
- 使用 Agent 后统一切换到 `/chat` 并清理旧 Agent 的会话状态。

### 3.6 MCP 传输

#### 规范化传输值

```text
stdio             本机程序（Local）
sse               SSE
streamable_http   Streamable HTTP
```

后端配置校验和前端选择器都支持这三种值。数据库或旧备份中的 `http` 按 `streamable_http` 兼容处理，读取时不让旧配置失效。

#### Local/stdio

沿用当前本机命令、参数、工作目录和环境变量配置，使用子进程 stdin/stdout 进行 JSON-RPC 通信。

#### SSE

- 对配置的 URL 建立 SSE 初始化连接；
- 读取服务端发送的初始化 endpoint 事件；
- 通过获得的消息 endpoint 发送 JSON-RPC 请求；
- 保留会话标识和 Bearer Token；
- 连接断开、缺少 endpoint 或响应无效时返回明确错误并清理连接状态。

#### Streamable HTTP

- 沿用当前 POST JSON-RPC 实现；
- 支持 JSON 响应和 `text/event-stream` 响应；
- 保留 `Mcp-Session-Id`；
- 使用 Bearer Token；
- 旧 `http` 配置按此方式连接。

三种类型在列表、连接确认提示、工具发现和断开/删除流程中使用同一套资源管理逻辑。

## 4. API 与数据流变化

### 新增或扩展接口

- `POST /api/models/test-connection`：测试未保存的候选模型配置；
- `POST /api/models`：保存前强制测试；
- `PATCH /api/models/{id}`：涉及连接字段时先测试候选值；
- `PUT /api/models/{id}/credentials`：替换密钥前测试新密钥；
- MCP 创建请求的 `transport` 支持 `stdio`、`sse`、`streamable_http`，兼容读取 `http`。

### 数据安全

- API Key 和 Bearer Token 只进入系统凭据库；
- 错误、日志、前端状态、备份和响应不包含明文秘密；
- 测试失败必须保持原配置不变；
- SSE 和 Streamable HTTP 的连接关闭时清理会话和进程状态。

## 5. 测试设计

### 后端测试

1. 模型候选测试成功/失败、字段错误、超时、认证失败；
2. 创建测试失败时数据库和凭据库无新增记录；
3. 编辑候选失败时原配置和原密钥不变；
4. 计划执行的执行阶段请求包含计划文本；
5. 计划步骤、重规划和上限停止事件；
6. 普通聊天和调试聊天只加载选中的 Skills；
7. Skill 缺失或损坏时返回可识别的运行告警；
8. Local、SSE、Streamable HTTP 的 MCP 配置、初始化、工具发现和 Token 传递；
9. 旧 `http` 配置兼容读取；
10. 原有工具审批、会话持久化和模型密钥安全测试不回归。

### 前端测试

1. 模型新增按钮先测试，失败保留草稿并展示错误；
2. Agent 模型选择项和摘要只显示显示名称；
3. 主聊天和调试聊天均包含 Enter 发送、Shift+Enter 换行和组合输入保护；
4. 计划卡、步骤状态和调试计划展示；
5. Agent Tab 与 `/agents` 使用同一个列表组件和操作回调；
6. MCP 选择器包含 Local、SSE、Streamable HTTP；
7. TypeScript typecheck 和 Vite build 成功。

### 真实应用烟测

- 启动后端和 Vite 前端；
- 在模型库用错误 URL、错误密钥、错误模型分别测试，确认不产生模型记录；
- 用成功配置创建模型并配置 Agent；
- 在普通聊天和调试聊天验证 Enter/Shift+Enter；
- 使用计划并执行任务，观察计划卡、步骤轨迹和模型请求结果；
- 勾选 Skill 后分别测试普通聊天和调试聊天；
- 在 Agent Tab、`/agents` 和配置页之间往返，确认列表一致；
- 检查三种 MCP 传输的配置和连接入口；
- 检查 `/api/health`、前端代理和生产构建。

## 6. 范围边界

本次不包含：

- 整体视觉风格重做；
- 将 Skill 改造为可独立点击或函数调用的 Tool；
- Dify、DSH 等第三方平台的实际接入；
- 新的模型市场、自动模型发现或批量导入；
- 重写 SQLite 数据层、会话协议或现有工具审批架构。

## 7. 已知环境限制

当前工作目录不是 Git 仓库，因此本设计文档无法执行 Git commit；实施时按修改文件和测试结果报告变更，不进行提交或合并操作。
