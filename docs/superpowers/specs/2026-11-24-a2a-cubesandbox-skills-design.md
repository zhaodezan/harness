# 应用内 A2A 委派、CubeSandbox 与 Skills 修复设计

**日期：** 2026-11-24  
**状态：** 用户确认，实施计划已就绪  
**实施顺序：** Skills 指引与资源 → 应用内 A2A → CubeSandbox 与 Skill 脚本接入

本文沿用现有 FastAPI、SQLite、React、PluginStore、工具授权与审批机制。不开放远程 A2A，也不将 CubeSandbox 服务端安装到 Windows。

## 1. Skills：勾选后在聊天中实际生效

### 指引与上下文

- 普通聊天使用 Agent 已保存的 `selected_skills`；调试聊天使用页面当前勾选的草稿。两条路径复用同一套 Skill 解析、加载和指引格式，保留已有 legacy 目录兼容逻辑。
- 显式选中的 `SKILL.md` 正文是适用于当前任务的操作指引，不再笼统标为参考资料。仅在适用时采用，不能覆盖系统约束、用户当前请求或应用层授权。Skill 正文不会被注册成可执行工具。
- 普通聊天当前的压缩分支会先用原始系统提示词和最近消息重建消息列表，后面再筛选 `system` 消息，已经移除的 Skill 指引不会因此恢复。把渲染后的系统提示词和 Skill 指引独立保留，只压缩历史对话；规划、执行和后续工具回合均保留当前指引。
- 普通聊天和调试运行轨迹显示已加载、未找到和读取失败的 Skill 名称及简要原因，不回显 Skill 正文。前端保留本次运行的 Skill 状态，不用最后一个「完成」事件覆盖告警。

### 包内资料与脚本

- 仅当当前 Agent 显式选中并成功加载 Skill 时，才允许读取该 Skill 包内的文本资料，例如 `references/format.md`；依需读取，不把整个包上传给模型。按 Skill 名称和相对路径定位，拒绝绝对路径、越界路径和符号链接，限制读取大小；不读取未选 Skill 或任意宿主文件。读取到的资料作为数据返回，不授予工具权限。
- 包内 Python 脚本经单独的工具入口请求执行，只接受所选 Skill 的包内路径。沿用同一路径校验，经用户逐次审批后，由 CubeSandbox 接收该脚本和显式列出的包内依赖。不会因为导入/勾选 Skill 或正文里出现命令就执行代码。服务未连接时只拒绝脚本执行，文本指引和资源读取继续可用。

## 2. A2A：同一应用内的 Agent 委派

- Agent 配置新增「可委派的智能体」，默认为空，只列出本应用中的其他 Agent。后端校验调用对象；任务分派前再次核验授权与目标是否仍存在。调试也不能通过构造请求获得配置之外的目标权限。删除目标时删除关联授权；导入备份时只恢复能映射到本应用内有效目标的授权。
- 父 Agent 通过运行时工具提交目标和简短任务。内部服务以 A2A 1.0 的协议模型构建 Agent Card、Message 和 Task，使用对应的状态和结果类型；数据结构以官方规范/协议定义为准。使用进程内传输，不开放外部发现、JSON-RPC 或远程接入；不把使用协议模型等同于完成外部互操作认证。
- 子 Agent 用自己的模型、系统提示词和已启用的 Skills 处理任务，不接收父 Agent 的完整历史、密钥、审批令牌或工具授权。子 Agent 的工具仍受自身授权和现有审批约束；不能转发审批的执行入口拒绝需要审批的操作。子结果作为任务输出交还父 Agent，不作为新指令。轨迹显示目标和任务状态，不记录敏感任务参数或凭据。
- 单次外层运行最多两层委派、总计最多四次任务调用、单次委派最长 60 秒；拒绝自调用及当前调用链上的循环。取消父运行时取消其子任务；无权、目标删除、超时或子任务失败时返回明确状态，不无限重试。首版不提供跨运行续聊、后台任务轮询或外部 Agent 互通。

## 3. CubeSandbox：代码不再在后端进程运行

### 连接与执行环境

- 「模型及插件库」新增全局 CubeSandbox 连接设置，保存受信任的服务地址、Python 模板和配额配置；凭据写入本机 SecretStore，响应只返回配置/连接状态。提供连接测试，按官方接口与所用版本核验 Python 模板能创建、执行并释放隔离实例。不让模型或插件自行提供服务地址、模板或凭据。
- Windows 后端是客户端；需要在受支持的 Linux/KVM 环境另行部署 CubeSandbox。没有配置、凭据无效、模板不满足隔离要求或服务不可用时，拒绝代码执行并提示检查连接；不会退回宿主执行。
- 每次调用使用独立的临时工作目录，不挂载宿主文件系统、不传宿主环境变量或其他凭据。仅发送源码、调用参数和针对本次运行选定的文件。按兼容优先允许沙箱通过服务端策略访问外网，但不开放宿主、内网管理端点或云元数据；无可执行所需网络/隔离策略的模板不启用。CPU、内存、进程和磁盘限额在沙箱服务端模板落实；应用另外限制调用时长、并发和输出。完成、超时或取消时释放沙箱。超时不等同于资源限制，不能只依赖客户端断开来落实配额。

### 三种入口共用隔离执行器

1. **已安装 Python Tools**：导入、编辑和启动扫描只解析 AST，要求 `TOOL` 为可静态解析的字典且有 `run` 函数；不导入模块，也不执行顶层代码。不能静态解析的旧工具显示明确错误。已授权 Tool 在调用时才把源码和参数送到沙箱；继续使用现有风险级别与审批机制。
2. **Agent 生成的 Python**：在 Agent 配置中显式启用，默认关闭。每次执行都由用户审批；审批显示本次拟执行代码；批准后只在沙箱运行。不提供宿主 shell、通用文件挂载或无需审批的后台执行路径。
3. **Skill 包内 Python 脚本**：按第 1 节验证路径与选择状态，审批后调用同一隔离执行器。不支持执行其他语言的包内脚本。Local/stdio MCP 与定时任务不属于本次迁移范围。

## 4. 验收与验证顺序

| 交付 | 验收项 |
| --- | --- |
| Skills | 使用可重复的测试 Skill ZIP，验证勾选与未勾选行为、普通聊天与调试实际模型请求、压缩后保留指引、包内文本可读、跨包和越界路径不可读、缺失/损坏在界面留有告警。等待实际失效的 Skill 包不是实施前提。 |
| A2A | 配置可保存和重新加载；父 Agent 收到授权目标结果；拒绝越权目标、自调用、调用环与超额委派；父任务取消时子任务退出；子 Agent 只使用自身配置和权限。 |
| CubeSandbox | 验证安装、编辑、启动均不在宿主执行源码；用替身验证连接失败时拒绝运行、代码/参数不泄露凭据、审批拒绝不调用沙箱、超时和取消释放实例。真实部署可用后，再验证 Python Tool、生成代码和 Skill 脚本从界面到隔离实例的执行，以及硬件隔离环境的限额策略。 |

每项先添加可观察的失败回归测试，再实现并运行专项测试。整体完成后运行后端全量测试、前端类型检查与生产构建，并通过实际启动的应用验证关键入口。没有真实 CubeSandbox 服务时，明确区分「客户端契约验证」与「真实沙箱联调未验证」。
