# Dify 市场工具插件独立运行

日期：2026-11-28

## 目标与范围

用户能在 Agent Harness 搜索 Dify Marketplace 或粘贴官方详情页链接，安装选定版本，把插件的工具勾选到 Agent，再在对话中调用。不部署或连接 Dify 服务，不要求 Dify 账号。Marketplace 是下载源；使用联网工具时，仍需该工具供应商的网络与凭据。另提供本机 `.difypkg` 手动导入，作为市场接口不可用时的安装方式。

第一版支持独立的 Python Tool 插件，包含静态参数、供应商 API Key 和文本/JSON 结果。暂不支持依赖 Dify 模型、知识库、工作流等宿主服务的能力，也不支持 OAuth、动态参数、文件输入输出和非工具类插件。不自动更新；用户可移除或安装其他版本。已知不兼容的包在预检阶段拒绝；如果某项宿主依赖只有在调用时才显现，运行时返回具体的不支持原因，不尝试连接 Dify。

## 单目录约束

Dify 的后端、前端、容器运行器、专用样例和测试全部位于 **`backend/app/dify_plugins/`**：

- Python 模块：市场适配、插件包校验、安装状态、路由、凭据和 `ToolRegistry` 桥接。
- `runner/`：Docker 构建配置、独立 SDK 运行入口和受限的请求/响应协议。
- `ui/`：Dify 市场与安装页面、供 Agent 配置页复用的工具选择组件及样式。
- `tests/`：市场与安装测试、协议样例、运行器测试和真实市场包联调说明。

现有系统只增加必要的挂载和导入：应用启动与路由注册、第三方插件页挂载、Agent 工具选择、构建与测试发现配置。Dify 的业务逻辑不写进现有页面、聊天运行时或 MCP 模块。插件文件与元数据位于应用数据目录下的 `dify-plugins/`，不写入源码目录。SDK 与插件依赖不安装到 Harness 的 Python 环境。

## 页面与官方市场嵌入

在「模型及插件库 → 第三方插件 → Dify」提供「官方市场」「本机安装」「已安装」。官方市场页面显示固定官网链接并在新标签页打开。Dify Marketplace 当前响应 `Content-Security-Policy: frame-ancestors 'none'` 与 `X-Frame-Options: DENY`，因此本系统不使用 iframe，不做代理、不移除响应头、不绕过官网策略。官网安装按钮不控制本机，也不把本机凭据发给官网。

本机安装独立提供官方链接解析、关键词搜索与 `.difypkg` 预检；嵌入失败或 Docker 停止不影响搜索和插件详情。非兼容、下载失败或没有结果时明确区分原因。安装须先预检并由用户确认固定版本与来源。

## 安装、运行与移除

1. **选择。** 市场客户端调用官方 Marketplace 接口搜索、读取元数据和定位包；仅接受官方详情页作为链接输入，不允许以用户输入的 URL 任意下载。下载和重定向仅允许经确认的官方分发端点。界面显示插件身份、固定版本和兼容性；版本变动不得在确认后静默生效。
2. **校验。** 在临时目录检查包体积、展开体积、成员数、重复成员、路径穿越、绝对路径、链接和嵌套依赖路径，安全解析 manifest、provider 与工具声明；不在宿主导入任何包内模块。记录原始包的 SHA-256，市场来源的身份和版本必须与包元数据一致，不把自算哈希当作签名。手动导入标明来源未经验证，用户需单独确认。
3. **安装。** 在独立 Linux Docker 构建环境安装依赖，复用项目的本机 Docker 探测方式，不复用只能执行单文件源码的现有 Worker。新增固定 Runner，使用容器内的 Dify Python SDK 接收工具请求，解析工具返回消息；不部署 Plugin Daemon，不实现或访问 Dify 内部 API。构建和运行均不挂载用户目录或 Docker socket，不传宿主凭据。容器运行用非 root、最少权限、资源与输出上限；Docker 不可用时不回退到宿主执行。解析、构建和运行器探测全部成功后才注册工具；失败不留下可调用项。
4. **授权并调用。** 分发包按内容固定，工具使用包含插件与版本标识的稳定 ID，借用现有 `selected_local_tools` 存储和注册表授权过滤；不冒充 MCP 工具或本地 `.py` 工具。插件未被勾选就不提供给模型。工具统一按可能有副作用处理，遵循现有对话审批策略。供应商凭据由系统凭据库分插件保存，不进入配置响应、日志或备份；调用时只传当前插件所需凭据。出站网络默认关闭，由用户按插件启用；启用时界面提示工具可把输入和自身凭据传出容器，它不是按域名限制的授权。
5. **恢复与移除。** 重启时只恢复已完成安装且所需容器镜像仍存在的工具；镜像缺失给出重装提示。插件卸载后立即停止新调用并撤销注册，清理插件凭据和本功能管理的安装产物。旧 Agent 选择不会隐式绑定到不同版本。备份可保留原有工具选择记录，但不导出插件包、镜像和密钥；恢复后需显式安装对应包才能调用。

安装失败、Docker 不可用、缺少凭据、未授权联网、不支持的能力和调用超时应分别提示；未经处理的插件异常、容器 stderr 与第三方凭据不直接显示或写入运行记录。

## 验收

- 不启动任何 Dify 服务，验证市场搜索或链接识别、固定版本下载、Docker 安装、Agent 单独勾选和实际对话调用。可使用市场中的独立工具；若所选工具需要供应商密钥，则用该工具的测试密钥并仅通过凭据设置输入。
- 使用本地协议样例自动测试成功路径，以及未勾选拒绝、现有审批策略、路径穿越与资源限制、版本不符、安装失败、宿主回调不支持、超时、凭据不回显、重启及移除。模拟市场和 Docker 的自动化测试不视为真实市场包联调通过。
- 构建前端并运行现有回归测试。当前机器已检测到 Docker CLI，但 Linux 容器引擎不可达；完成真实安装验收前需要引擎可用，不以模拟测试替代。
