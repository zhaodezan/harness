# Python Agent Harness 需求说明书（首版）

- **文档状态**：设计稿，待用户评审
- **版本**：0.1
- **日期**：2026-11-20
- **项目定位**：个人本地使用的 Agent Web 应用

## 1. 项目概述

建设一套以 Python 为后端的 Agent Harness，并提供相应 Web 前端。用户可通过浏览器与 Agent 对话，也可在管理控制台配置模型、MCP Server、Skills、Python 工具和 Prompt。

本产品首版重点是通用对话与知识助手，以及可扩展、可观测、具有基本安全边界的工具调用闭环。首版自建精简 Agent Runtime，支持 ReAct 和 Plan-Execute 两种运行模式，不绑定大型 Agent 编排框架；Multi-Agent 协作规划为下一版本。

## 2. 目标与非目标

### 2.1 首版目标

1. 提供本机运行的 Web 对话工作台与管理控制台。
2. 支持 OpenAI 兼容模型服务，完成多轮对话和流式响应。
3. 支持 MCP stdio 与远程 HTTP Server，并使用其暴露的工具。
4. 支持从本地目录发现 Skills，并支持手动选择及按任务自动选择。
5. 提供开发者可调用的 Python 工具注册接口。
6. 将具有副作用的工具调用置于用户审批之后。
7. 在本地持久化会话、配置和长期记忆，并提供导入/导出及清理入口。
8. 提供跨会话长期记忆能力，并在上下文接近模型限制时自动总结较早历史，避免请求超限。
9. 提供运行轨迹和调试信息，便于理解工具调用、错误和消耗。
10. 支持 ReAct 与 Plan-Execute 两种单 Agent 运行模式，用户可按 Agent 配置选择。
11. 提供一键本机启动、环境检查和开箱即用的 Agent/MCP 配置模板，降低首次使用门槛。
12. 支持搜索历史会话，并可通过重新生成或从历史消息分支继续对话。

### 2.2 首版非目标

- 多用户登录、团队/租户隔离和复杂角色权限。
- 默认远程部署或公网访问。
- Multi-Agent 协作（规划在下一版本实现）及通用工作流图编排。
- 文档上传、向量索引及完整 RAG 知识库。
- Agent 任意执行本地命令或任意读写文件。
- 通过 UI 编写或执行任意 Python 代码。
- 复杂 Prompt 模块继承、条件片段和可视化编排。

### 2.3 下一版本规划（不属于首版验收范围）

1. **Multi-Agent 模式**：支持主 Agent 将复杂任务拆分并委派给受约束的子 Agent，汇总结果并展示协作轨迹；角色、并发数、独立上下文、预算和权限继承规则在下一版本需求设计时确定。
2. **发布 Agent 为独立聊天页面**：用户可将配置好的 Agent 部署为一个独立可访问的聊天页面；不做 Agent 市场、社区发现或供其他人复制/导入配置的分享平台。部署位置、访问控制和页面 URL 规则在下一版本需求设计时确定。
3. **自定义聊天界面品牌**：用户可为独立聊天页面配置展示名称和 Logo。品牌资源格式、尺寸、主题范围及发布后的更新策略在下一版本需求设计时确定。
4. **Agent 评测**：用户可维护一组测试任务，对指定 Agent/Prompt/运行模式批量运行并查看结果、运行轨迹、耗时和 Token 用量；支持人工评分与版本对比。自动模型评审、外部评测平台集成和复杂评测编排不在该轻量版范围内。
5. **首版后续增强项**：改善安装器对已安装依赖的重复运行体验；支持 MCP OAuth 和更多 HTTP 认证头/环境变量配置；按需增加模型供应商能力预设和更完整的费用分析；补充真实浏览器可访问性、并发/断线/恢复测试；完善备份导入冲突回滚。上述均为增强项，不阻塞当前首版可运行版本。

上述功能作为下一版本方向记录，不纳入首版验收范围或交付承诺；首版只做必要的轻量扩展边界，不提前实现多 Agent 协调框架、发布平台或多租户体系。

## 3. 用户与运行环境

- **目标用户**：单一个人用户/开发者。
- **交互方式**：现代浏览器访问本机服务。
- **运行方式**：本机开发运行；首版不要求 Docker 或生产级远程部署。
- **网络边界**：后端默认只监听本机回环地址，不默认暴露至局域网或公网。

## 4. 系统架构

### 4.1 子系统划分

首版按逻辑模块划分职责，但统一作为本机应用部署；不拆成微服务。为控制依赖和复杂度，相关能力尽量合并在已有模块中，不因每项功能另建服务。

1. **Web 前端**：React + TypeScript；提供对话工作台、管理控制台、运行轨迹和审批交互。
2. **应用/API 层**：Python + FastAPI；承载本地 Web API、配置管理、首次启动向导和健康诊断。
3. **Agent Runtime**：维护单次运行状态，负责组装模型请求、处理模型响应、调度工具、执行审批流程、管理运行限制、续跑或结束；首版用轻量运行策略支持 ReAct 和 Plan-Execute，共享模型、工具、记忆、审批和事件能力。
4. **模型适配器**：首版接入 OpenAI 兼容接口，将请求、流式事件和错误统一为内部协议；具体模型/服务地址由用户配置。
5. **扩展能力管理**：一个统一注册/发现入口，包含 MCP 连接管理（stdio/HTTP）、Skills 加载和 Python 工具注册；工具调用由 Runtime 统一调度。
6. **会话、上下文与记忆模块**：管理会话历史、Prompt/Agent 版本绑定、长期记忆、上下文压缩、上下文/调用预算和运行恢复状态。长期记忆与压缩后的会话摘要是不同数据类型；作为 Runtime 周边的轻量模块，不要求独立服务。
7. **权限与审批策略**：管理工具风险分类、审批和授权结果；由 Runtime 在执行工具前强制检查。
8. **事件、诊断与日志模块**：统一处理模型、工具、审批、运行状态和错误事件，支持前端流式轨迹及持久化查询；可与 API/Runtime 共进程运行。
9. **本地存储模块**：SQLite 保存会话、Agent 配置、连接/工具配置、Prompt 版本、长期记忆、压缩摘要及结构化运行日志；日志保留 30 天后自动清理。密钥优先使用操作系统凭据存储，不可用时采用明确的本地加密存储方式。

### 4.2 关键设计原则

- **依赖尽可能少**：只引入满足首版明确需求的直接依赖；优先使用 Python 标准库、浏览器原生能力和已有基础组件，避免功能重叠的库、过度抽象的框架及非必要运行时服务。每项新增依赖都应说明必要性、维护状态和替代方案；安全、协议兼容或显著降低维护成本的依赖可合理引入。
- **用户使用必须简单（硬性原则）**：这是首要产品原则，不因内部架构、配置灵活性或功能数量而牺牲。常见任务通过合理默认值、向导和清晰步骤完成；用户无需理解 Harness/MCP/上下文等内部术语，也无需手工编辑配置文件即可完成首次启动、常见模型连接和基本对话。复杂选项采用渐进式展示，默认路径保持简短；错误用通俗语言说明原因并给出可执行的下一步。简化交互不得绕过安全审批或隐藏重要风险。
- **前端必须美观、炫酷且有完成度**：采用统一且鲜明的现代科技视觉语言，重视版式层级、色彩、排版、图标、动效和运行状态呈现；避免默认模板感、未样式化控件和信息堆砌。视觉效果不能损害易用性、可读性、可访问性或响应性能，视觉方向采用高级简约：以清爽留白、精致排版、克制的科技感色彩和细腻动效营造质感，避免霓虹堆叠与过度装饰。
- Runtime 不直接依赖单一模型提供商、MCP SDK 或前端实现；通过明确接口隔离。抽象边界应轻量，不能为了可替换性引入多层无实际价值的依赖或框架。
- 以共享的最小 Runtime 能力为核心，通过轻量模式策略支持 ReAct 与 Plan-Execute；不在首版实现通用工作流引擎或 Multi-Agent 协调。
- 工具的权限、审批、超时和错误处理必须由 Harness 执行，不能只靠 Prompt 约束。
- 配置与运行数据采用稳定、可导入/导出的格式，避免数据只能通过 UI 访问。

## 5. 功能需求

### 5.1 Agent 与模型配置

- 用户可创建、编辑、复制和删除 Agent 配置。
- 每个 Agent 至少包含名称、模型服务配置、模型标识、系统 Prompt、启用工具/Skills 和运行限制。
- 支持配置 OpenAI 兼容服务的 API Base URL、模型名及认证凭据。
- 认证凭据写入安全密钥存储，界面默认掩码显示。
- 首次启动提供简短配置向导，帮助完成模型配置、存储检查和基本诊断；可跳过并稍后继续。
- 提供一键本机启动入口：检查运行环境和端口，启动后自动打开浏览器；启动失败时说明原因及可执行的修复步骤，不要求用户自行查找命令行参数。
- 提供开箱即用的 Agent 模板（至少包含基础对话助手和 Plan-Execute 助手）及通用 OpenAI 兼容模型/MCP 配置示例；用户可预览并创建副本，不覆盖已有配置；模板不包含真实凭据。
- 用户可测试模型连接；失败时区分网络、认证、模型/能力不支持和配置错误，且不在日志中暴露凭据。
- 支持检查应用健康状态与 MCP Server 连接状态，并为可恢复问题提供重试入口。

### 5.2 对话与会话

- 用户可创建、重命名、切换和删除会话；可按标题或消息内容搜索历史会话，并从搜索结果定位到对应消息。
- 会话绑定其 Agent 配置；对话历史和运行状态在本地持久化。
- 页面刷新或服务重启后，保存的会话可继续查看。
- 模型回复以流式方式显示；用户可取消进行中的运行。
- 用户可重新生成一条回答（保留旧回答），或从历史用户消息编辑内容并分支继续对话；分支为独立会话，原会话和历史消息保持不变。
- 创建分支只复用已有对话上下文，不重放分支点之前的工具调用；分支运行中新发起的工具调用遵循正常权限审批、预算和日志规则。
- 服务重启后，未完成的运行应标记为中断并保留已保存记录；不得未经用户操作自动重放工具调用。
- 模型或工具发生可恢复错误时，用户可显式重试；有副作用的工具调用重试前必须重新执行审批。
- 支持清理会话数据，并提供会话和配置的导出/导入能力。

### 5.3 Agent 运行模式与运行循环

- 每个 Agent 可选择运行模式；默认使用 ReAct，模式选择以简短说明呈现，不要求用户理解内部实现术语。
- **ReAct**：模型在同一循环中根据当前上下文进行判断、调用工具、读取结果并继续，直到完成、取消或触发运行限制。
- **Plan-Execute**：先生成可读的分步计划，生成后立即开始执行，不等待用户批准整份计划；逐步显示步骤状态。执行遇到错误或计划前提变化时可在运行预算内重新规划。计划与执行共用现有模型、工具、记忆、审批、超时和取消机制，不额外要求一个规划模型。
- 计划步骤仅作为执行进度和运行控制，不构成工具授权；副作用工具仍遵循既有逐次确认规则。用户可查看计划与执行进度并随时取消，但不需要批准计划后才能开始。
- Runtime 接收用户消息，构造模型输入并调用模型。
- 当模型返回工具调用时，Runtime 校验工具存在、参数符合 Schema、调用处于允许范围内。
- 对获准调用执行工具并将结果回传模型；循环直至模型给出最终回答、达到运行限制或发生不可恢复错误。
- 支持可配置的单轮最大工具调用次数、模型请求超时、工具执行超时和输出/上下文预算。
- 在接近或达到模型上下文限制时给出明确提示和可操作的处理方式；超大工具结果不得静默截断，应使用明确的上限/摘要策略并标明已省略内容。
- 运行次数、模型请求和工具执行应可取消；取消后不再发起新的工具调用。
- 对重复调用、无效参数、超时、连接失败和模型错误提供结构化错误结果，避免运行无限循环。

### 5.4 MCP

- 首版支持本机 stdio MCP Server 与远程 HTTP MCP Server。
- 用户可配置 Server 名称、传输方式、启动命令/参数或远程地址，以及所需环境变量/认证信息。
- 首次启动本机 stdio Server 前，界面需展示将启动的命令和参数并要求用户确认；机密环境变量需掩码显示。
- 提供连接、断开、重连、连接状态和工具发现能力；工具名称冲突时必须显式提示并采用确定性的命名空间，不得静默覆盖。
- MCP 工具调用纳入统一运行轨迹和审批策略。
- Server 配置中的密钥/令牌必须安全存储并脱敏展示。
- MCP Server 连接失败时，展示 Server 名称、阶段和可操作错误信息；失败的 Server 不应阻塞无关 Agent 配置操作。

### 5.5 Skills

- 从用户配置的本地目录发现 Skill；每项 Skill 至少有名称、描述和指令内容。
- 首版兼容以 `SKILL.md` 为入口的目录式 Skill 格式；具体解析规则应在实现设计中固定并附示例。
- 支持在 Agent/会话中手动启用或禁用 Skill。
- 支持根据任务描述自动选择相关 Skill，并在需要时按需加载完整指令。
- Skill 内容视为不可信指令数据，不得覆盖系统级安全策略或 Harness 的权限策略。
- Skill 缺失、格式无效或加载失败时，提示错误并允许会话继续（除非用户明确要求该 Skill 为必需项）。

### 5.6 工具

- Python 工具由开发者通过代码注册，不允许在 UI 中提交任意可执行代码。
- 工具定义包含唯一名称、用途描述、参数 Schema、调用函数和权限分类。
- 前端可查看工具、启用/禁用工具，并查看其权限/审批策略。
- 统一管理 Python 工具与 MCP 工具的发现、参数校验、调用结果、错误和运行轨迹。
- 未注册、已禁用或参数验证失败的工具调用不得执行。

### 5.7 工具审批与权限

- 只读工具可按配置自动执行。
- 有写入、发送、删除或其他外部副作用的工具调用必须在执行前取得用户逐次确认。
- 审批界面至少展示工具名称、拟执行操作、关键参数和目标资源；敏感参数应掩码。
- 等待审批期间暂停该次 Agent 运行。
- 用户批准后仅执行本次展示的调用；用户拒绝后不执行，并将拒绝状态反馈给 Runtime/模型。
- 每次审批结果记录在运行轨迹中。
- 未被明确分类的工具默认按需要审批处理，避免将未知工具自动视为只读。

### 5.8 Prompt 管理

- 每个 Agent 支持编辑系统 Prompt。
- 支持明确格式的变量占位符；保存前可预览变量解析结果。
- 支持保留历史版本、查看版本时间/说明和切换到历史版本。
- 可在保存/启用前进行临时试运行，预览解析后的 Prompt、启用的 Skills 和可用工具；试运行内容与正式会话隔离。
- Prompt 编辑不包含模块继承、条件片段或复杂流程编排。
- Prompt 版本变更不应改写既有会话的原始记录；运行时需明确采用当前版本或会话绑定版本，具体默认策略在实现前确定并记录。

### 5.9 运行轨迹与调试面板

- 对话页面显示流式回复和按时间排序的运行轨迹；每次运行可展开查看完整事件链。
- 轨迹至少包括用户消息接收、模型请求开始/完成、Skills/记忆加载摘要、工具调用开始/结束、审批等待/结果、上下文压缩、错误、取消和最终完成；不记录或展示模型隐藏推理内容。
- 工具事件显示名称、状态、耗时、脱敏后的参数摘要和结果摘要；模型步骤显示模型标识、耗时、Token 用量（若服务返回）及错误详情。
- 调试面板展示可用的请求/响应摘要、模型标识、Token 用量（若服务返回）、耗时及错误详情。
- 原始调试数据应遵循最小化原则；认证头、API Key、访问令牌和敏感环境变量必须脱敏。
- 日志与调试数据不得被当作模型指令；需区分可信控制数据和外部工具/模型返回内容。

### 5.10 长期记忆与上下文压缩

**长期记忆**
- 支持跨会话保存用户偏好、稳定事实和任务背景；记忆是独立记录，不等同于完整对话历史。
- 新会话根据当前任务检索相关记忆，不将全部历史记忆无差别塞入模型上下文。
- 用户可查看、编辑、删除单条记忆并清空记忆库；可追溯记忆来源和创建/更新时间。
- 用户可明确要求保存记忆；Agent 可提出记忆候选，默认需用户确认后保存。用户可选择启用非敏感记忆的自动保存；凭据/认证信息不得自动保存。
- 默认不把凭据、认证信息或完整原始对话写入记忆；对敏感内容采取拒绝写入或要求确认的策略。
- 记忆按用户本地数据保存；每条记忆需有明确作用范围（全局或指定 Agent），避免不同 Agent 间意外共享。

**上下文压缩**
- Runtime 根据所选模型的上下文限制、已知用量和预留输出预算估算剩余空间；接近可用上限时自动总结较早历史，保留近期消息供后续推理。
- OpenAI 兼容服务未提供上下文上限或 Token 用量时，使用用户可配置的模型上下文窗口/保守默认值，并明确显示估算性质。
- 压缩摘要应保留目标、约束、用户偏好、已确认决策、关键事实和未完成事项；工具调用与结果应以完整成对记录或经校验的摘要保留，不能造成无效对话序列。
- 原始会话记录保持不变；摘要是可追溯的派生上下文，可查看压缩时间和摘要内容。
- 压缩失败或预算仍不足时，提示用户并停止发起超限请求；不得静默丢弃历史或未完成任务信息。

### 5.11 持久化日志管理

- 持久化本机应用运行日志及 Agent 执行轨迹，包括时间、级别、子系统、运行/会话标识、阶段、状态、耗时和错误类别等结构化字段。
- 每次 Agent 运行可从日志中重建按时间排序的执行轨迹，包含模型请求、Skills/记忆加载摘要、上下文压缩、工具调用及结果摘要、审批、错误和最终状态；不记录隐藏推理内容。
- 日志保留最近 30 天；超过保留期限的日志自动清理。清理不得影响会话对话记录和长期记忆。
- 前端提供日志查询，至少支持按时间范围、级别、子系统、会话/运行标识筛选，并支持关键词搜索。
- 用户可将查询结果或选定时间范围的日志导出为 JSONL 或 CSV；导出遵循相同脱敏规则。
- 日志默认不包含完整 Prompt、完整模型响应、认证头、API Key、Token 或敏感环境变量；必要的诊断摘要需脱敏。
- 为减少依赖，日志与运行事件复用现有 SQLite 持久化，不额外引入日志服务；普通 Python 运行日志采用标准库能力。

## 6. 前端页面范围

1. **对话工作台**：会话列表与内容搜索、消息区域、输入框、回答重试/重新生成、从历史消息分支、流式状态、运行轨迹、审批弹窗和调试面板。
2. **Agent 管理**：Agent 列表、从内置模板创建、模型配置、ReAct/Plan-Execute 模式选择、Prompt 编辑/版本、工具和 Skills 绑定、运行限制。
3. **MCP 管理**：Server 列表、stdio/HTTP 配置、连接状态、工具发现和启停。
4. **Skills 管理**：Skills 目录配置、发现结果、错误提示、启用/禁用。
5. **Python Tools 查看**：显示已注册工具及其描述、参数和权限；不提供代码编辑执行。
6. **本地数据管理**：导入/导出、清理会话和配置、密钥状态提示。
7. **记忆管理**：查看、搜索/筛选、编辑和删除长期记忆，区分全局与指定 Agent 作用范围；查看会话压缩摘要及其生成时间。
8. **日志管理**：按时间、级别、子系统、会话/运行标识筛选并关键词搜索；按时间线查看单次 Agent 的完整运行轨迹；支持 JSONL/CSV 导出，展示日志保留期限。

## 7. 非功能需求

### 7.1 安全

- 本机 Web/API 服务默认仅绑定 `127.0.0.1` 或等效回环地址。
- 限制跨源请求；不得允许任意网站无保护访问本地 API。
- 对 API 凭据、MCP 认证值及敏感参数采用安全存储和脱敏策略。
- 工具参数必须按 Schema 校验；文件/命令执行能力首版关闭。
- MCP Server 的本机进程启动参数与远程连接信息需作为不可信配置处理，并在错误信息中避免回显秘密。

### 7.2 可靠性

- 处理网络断开、模型限流/服务端错误、MCP 断连、工具超时和无效响应。
- 对可重试错误采用有限次数、可观测的退避策略；不可重试的配置/参数错误不应盲目重试。
- 运行循环有明确的调用次数、超时和取消边界。
- SQLite 写入需保证会话记录和运行事件在异常结束后保持一致性；启动时能检测并恢复/标记未完成运行。

### 7.3 可观测性

- 每次运行有唯一标识，事件按运行与会话关联。
- 记录模型/工具耗时、错误类别及 Token 用量（若可得）。
- 日志可配置级别，持久化保留最近 30 天并自动清理过期记录。
- 前端支持日志搜索和 JSONL/CSV 导出；日志与运行轨迹默认脱敏，不记录密钥、认证头或完整 Prompt/响应正文。

### 7.4 可维护性与可测试性

- 模型适配、MCP、Skills、工具注册、权限审批、Runtime、持久化和 API 层可独立测试。
- 关键接口有类型定义和 Schema 验证。
- 新增第三方依赖需经过必要性审查：优先复用已有依赖或标准库，不引入重复解决同一问题的库；运行时依赖与开发/测试依赖区分管理，并记录选择理由。
- 自动化测试覆盖运行循环、并行/连续工具调用（若实现支持）、审批拒绝/批准、超时、取消、持久化恢复和敏感信息脱敏。
- 提供本机启动说明、配置示例、MCP 示例和 Python 工具注册示例。

### 7.5 前端视觉质量与可访问性

- 所有核心页面采用统一的视觉设计系统；关键状态（加载、空状态、成功、错误、审批、运行中/完成）均有完整视觉反馈。
- 动效用于强化操作反馈和运行过程理解，保持流畅、克制，并尊重系统减少动态效果设置。
- 界面在常见桌面和移动浏览器尺寸下保持可读、可操作；颜色对比、键盘操作和焦点状态满足基本可访问性要求。
- “美观、炫酷”必须与“用户使用简单”同时满足：视觉装饰不得遮挡主要操作、堆叠信息或降低文字可读性。

## 8. 核心验收标准

1. 首次启动向导可完成必要配置检查；模型连接测试能区分常见配置/认证/网络错误且不泄露密钥。
2. 配置一个 OpenAI 兼容服务后，用户可完成多轮对话；回答在浏览器逐步呈现。
3. 刷新页面和重启后，已保存会话、Agent 配置和 Prompt 版本仍可查看；重启时未完成运行被标记为中断，工具调用不会自动重放。
4. 可连接一个 stdio MCP Server 和一个 HTTP MCP Server，发现其工具并通过 Agent 发起调用；首次启动 stdio Server 前需确认，工具名冲突有明确提示。
5. 无副作用且标记为只读的工具可按策略自动运行；未分类或有副作用的工具在获批前绝不执行。
6. 拒绝审批后，工具函数未被调用，运行轨迹中记录拒绝，并向 Agent 返回拒绝结果。
7. Python 注册工具可被模型发现并调用；UI 无法新增任意 Python 代码。
8. Skills 可从目录发现；用户可手动选择；自动选择模式只向模型加载相关 Skill 的完整指令。
9. Prompt 支持变量、保存历史版本和切换版本；可隔离试运行并查看实际生效配置；切换行为不篡改旧会话历史。
10. 调试面板能够查看运行事件、工具状态、耗时、错误和可用 Token 用量；测试凭据不会出现在日志/界面明文中。
11. 用户可取消正在运行的请求；取消后 Runtime 不再启动新的工具调用。模型/工具显式重试时，副作用调用需重新审批。
12. 默认监听地址为回环地址，且不接受未授权跨源浏览器调用。
13. 单轮工具循环受到调用次数、超时和上下文/输出预算限制；工具结果过大时不会静默截断，工具故障不会导致无限运行。
14. 用户明确要求保存的记忆可跨新会话检索；默认自动生成的记忆先待确认，启用自动保存后非敏感记忆可自动持久化；用户可查看、编辑、删除和清空记忆。
15. 长期记忆按全局或指定 Agent 作用域隔离；凭据与完整原始对话不会未经确认写入记忆。
16. 达到配置的上下文触发阈值时，Runtime 自动压缩较早历史并保留近期消息；原始历史不被修改，摘要可查看。
17. 模型上下文限制未知或压缩失败时，系统明确提示并停止超限请求，不会静默删除历史内容或自动重复工具调用。
18. 应用日志与 Agent 逐步运行轨迹持久化保存 30 天，过期后自动清理；日志管理页面能按运行/会话查看时间顺序的完整执行事件链，并按约定字段搜索/筛选、导出 JSONL/CSV。
19. 日志持久化、搜索和导出的结果均不包含明文凭据、认证头、模型隐藏推理或完整 Prompt/响应正文。
20. 普通用户无需阅读技术文档、理解内部术语或手工编辑配置文件，即可通过默认引导完成首次启动、常见模型连接和第一次对话；错误提示通俗并给出明确的下一步操作，且不以简化为由绕过安全审批。
21. Agent 可选 ReAct 或 Plan-Execute，ReAct 为默认；ReAct 能完成工具调用循环，Plan-Execute 能生成可读计划并立即开始执行、逐步显示执行状态，并在错误/计划前提变化时于预算内重新规划。
22. 两种模式均遵循相同的工具审批、调用预算、超时、取消、日志脱敏和运行轨迹规则；Plan-Execute 不等待整份计划的用户批准，但副作用工具仍逐次审批。首版不启用 Multi-Agent 协作。
23. 用户可通过单一启动入口运行应用并自动打开浏览器；环境缺失、端口冲突或启动失败时有清晰诊断和修复指引。
24. 用户可从内置 Agent 模板创建独立副本，并查看通用模型/MCP 配置示例；模板无凭据且不会覆盖既有配置。
25. 前端关键页面遵循经确认的统一视觉方案，具备完整状态反馈、良好可读性和流畅但克制的动效；在常见屏幕尺寸下可操作，不使用未定制的默认模板界面。
26. 用户可通过标题或消息内容搜索历史会话，搜索结果可定位到匹配消息。
27. 重新生成回答会保留原回答；从历史用户消息分支会生成独立会话，原会话不变，且不会重放分支点之前的工具调用；新分支中的副作用工具仍按规则逐次审批。

## 9. 待确认事项与建议默认值

以下事项不阻塞需求稿，但应在技术设计/实现前确定：

1. **允许的本地文件能力**：当前已明确首版不开放任意文件/命令执行；若未来加文件读取，建议只允许用户指定目录只读并防止路径越界。
2. **HTTP MCP 传输细节**：实现前确认采用的 MCP HTTP 传输版本、认证方式及是否需要 SSE 兼容。
3. **Skills 自动选择策略**：首版是否由模型根据 Skill 名称/描述选择，或由规则/用户选择与模型判断混合；应避免无约束地把所有 Skill 正文塞入上下文。
4. **Prompt 会话绑定策略**：建议新会话使用最新 Prompt，已有会话固定绑定创建时版本；用户显式切换后再更新绑定。
5. **密钥存储回退方案**：优先系统凭据库；如果当前系统不支持，明确加密密钥由何处保护，不得静默退化为明文。
6. **导入/导出格式**：建议配置导出不包含秘密值；会话导出可单独选择是否包含完整消息内容。
7. **模型能力差异**：OpenAI 兼容仅表示接口形态相似，不保证所有模型都支持工具调用、流式响应和同一参数；应实现能力检测或友好错误。
8. **依赖与最低运行版本**：Python、Node.js、浏览器和操作系统最低版本由实现阶段确定。
9. **开源/许可证与分发方式**：尚未指定，首版先按本机开发运行交付。

## 10. 术语

- **Harness**：管理模型调用、上下文、工具执行、权限、事件与数据持久化的 Agent 运行框架。
- **MCP**：Model Context Protocol；本项目通过 MCP Server 获得外部工具能力。
- **Skill**：通过目录和 Markdown 指令描述的可按需加载任务能力，不等同于可执行工具。
- **Python Tool**：通过项目 Python API 注册、由后端执行并受 Harness 权限控制的函数。
- **副作用工具**：可能改变数据、发送信息、触发外部操作或产生不可轻易撤销影响的工具。
