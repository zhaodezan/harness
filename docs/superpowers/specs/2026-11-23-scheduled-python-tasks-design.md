# 本地 Python 定时任务设计

日期：2026-11-23  
状态：功能方向已确认，待实施

## 目标与范围

工作区侧栏增加独立「定时任务」入口（`/scheduled-tasks`）。任务由用户编写 Python 脚本并设置执行时间，不绑定 Agent、数据库或固定操作模板。首版不支持无服务器后台执行，不注册操作系统计划任务，也不让 Agent 创建、启用或触发脚本。

## 页面与操作

- 列表显示任务名、Cron、时区、启用状态、下次执行时间和最近结果。
- 新建与编辑支持任务名、脚本、五段式 Cron、IANA 时区和执行超时。保存前验证 Cron 和 Python 语法，不执行脚本；预览下一次触发时间并显示时区。配置和运行记录由应用本地 SQLite 管理。
- 新建任务默认停用。启用前显式确认当前脚本版本；暂停后不再触发新运行，已启动的一轮可结束。修改脚本保存后停用旧计划，必须重新确认才能启用新版本。正在等待执行的旧版本不能在编辑或停用后开始执行。
- 「立即运行」不改变启用状态或下次触发时间。调用前须显式确认本次运行的脚本版本；如果同个任务正在运行，返回冲突而不是排队。
- 支持删除。正在运行的任务不允许删除，以免失去可追踪记录；删除操作注明同时移除应用内的运行历史。

## 调度与执行

- 后端启动时加载已启用且已确认版本的任务，按当前时间计算下一次触发，不补跑离线期间错过的轮次。关闭浏览器不影响调度，但后端必须运行。同一任务上一轮未结束时跳过本轮并记录原因；重复调度不得同时启动两轮。
- 调度及手动运行使用同一个执行入口，绑定已确认的脚本版本。每轮由本机 Python 解释器在单独子进程中运行，不经 shell，不使用请求指定的解释器或命令；用独立工作目录及最小化环境变量，超时后停止任务进程并记录状态。后端意外退出后将未完成记录标为中断，不把它们当成应补跑的触发。
- 用户脚本是受信任代码。子进程不是安全沙箱，脚本仍可按后端账户权限访问系统资源。不自动向脚本注入模型、MCP 或数据库连接凭据；不要在脚本或输出中填写密钥。本机管理接口沿用本地访问限制，确认操作与脚本版本绑定，不注册为 Agent 工具。

## 运行记录

每次执行记录其触发方式、计划时间、实际开始和结束时间、耗时、退出码及状态（成功、失败、超时、跳过或中断）。任务详情可查看限长的标准输出和错误输出，并标记截断；输出不进入聊天记录、不发给模型。运行记录按任务分页查看，不在任务列表加载全文。

## 验收

- 新建停用、预览合法 Cron、拒绝无效 Cron/时区/脚本；保存新脚本后不能沿用旧批准。
- 使用可控时钟验证时区、重启不补跑、暂停以及同任务不重叠；在 Windows 上实际运行短 Python 脚本验证结果、失败码、输出截断和超时清理。
- 「立即运行」确认绑定版本且不改调度时间；调度历史可区分自动与手动触发。Agent 不能通过应用工具创建、启用或触发任务。
- 「数据库」与「定时任务」分别有独立路由及导航状态，不替换知识库、长期记忆或运行记录入口。
